# To-Do List: Vue 3, Pinia и Vue Router

Продолжение To-Do. Приложение получило **регистрацию, вход и выход**, **личные списки задач** для каждого пользователя и страницу «О приложении». Состояние организовано через **Pinia**, переходами между страницами управляет **Vue Router**.

- **Автор:** Беседин Кирилл Дмитриевич, ФИТ-241
- **Опубликованное приложение:** https://sognatore-coder.github.io/To-doList_js/

> ⚠️ **Авторизация учебная, без сервера.** Аккаунты, пароли (в виде солёного хэша) и состояние входа лежат в `localStorage` браузера и доступны скриптам страницы. Это демонстрация сценария, а не защита реальных учётных записей: используйте только вымышленные email и пароли, которые нигде больше не применяются. Настоящая авторизация требует серверной проверки и безопасного хранения паролей.

## Возможности

- **Регистрация** — email, пароль и подтверждение. Проверяются формат email, длина пароля (от 6 символов), совпадение паролей и отсутствие пользователя с таким email; ошибки показываются у полей. После регистрации открывается страница входа.
- **Вход и выход** — вход по email и паролю, при неверных данных — ошибка. После входа открывается страница задач (или страница, на которую пользователь пытался попасть). «Выйти» завершает текущий вход; аккаунты и задачи сохраняются.
- **Личные задачи** — на странице задач видны и изменяются только задачи текущего пользователя. Каждая задача хранит устойчивый `userId` владельца.
- **Операции To-Do из лабы №6** — добавление (модальное окно), редактирование, удаление с подтверждением, отметка выполненной (выполненные зачёркнуты и уходят вниз), поиск по названию и фильтры.
- **Страница «О приложении»** — описание, живая статистика из сторов, стек, история разработки.
- **Тема** — светлая и тёмная, выбор запоминается.
- **Адаптивность и доступность** (A1–A7): подписи у всех полей, `aria-describedby` и `role="alert"` для ошибок, `aria-current="page"` в навигации, управление с клавиатуры, видимый фокус, модальные окна на `<dialog>`; при переходе между страницами фокус переносится на заголовок новой страницы, `document.title` обновляется.

## Маршруты

| Путь | Страница | Доступ |
| --- | --- | --- |
| `#/login` | `LoginPage.vue` | только гостям |
| `#/register` | `RegisterPage.vue` | только гостям |
| `#/todo` | `TodoPage.vue` | только вошедшим |
| `#/about` | `AboutPage.vue` | всем |

`#/` и неизвестные адреса перенаправляются на `#/todo`, а оттуда гость попадает на вход.

**Guard** (`router/index.js`): гость, открывший `#/todo` — в том числе по прямой ссылке или обновлением страницы — перенаправляется на `#/login?redirect=/todo`; после входа его возвращают на запрошенную страницу. Состояние входа к первой навигации уже восстановлено из `localStorage`, поэтому обновление страницы вошедшего пользователя оставляет его в системе. Вошедший пользователь при заходе на вход или регистрацию попадает на страницу задач.

**Режим истории — `createWebHashHistory()`.** Адреса вида `…/To-doList_js/#/todo` работают на GitHub Pages без настройки хостинга: прямые ссылки и обновление страницы не дают 404.

## Сторы (Pinia)

Плагин `pinia-plugin-persistedstate` подключён к экземпляру Pinia в `main.js`, а в нужных сторах включён `persist`.

- **`useUserStore`** (`stores/user.js`) — `users` и `currentUserId`; геттеры `currentUser`, `isAuthenticated`; действия `register`, `login`, `logout`. Сохраняется всё состояние (ключ `todo-app:users`), поэтому после обновления страницы пользователь остаётся в системе.
- **`useTodoStore`** (`stores/todo.js`) — `todos` всех пользователей (каждая задача с `userId`), а также `query` и `filter`. Геттер `myTodos` отдаёт только задачи текущего пользователя, `visibleTodos` применяет к ним поиск, фильтр и сортировку, все действия работают только со «своими» задачами. Сохраняются только `todos` (ключ `todo-app:todos`, опция `pick`); поиск и фильтр после перезагрузки сбрасываются, при выходе — тоже.

Некорректные данные в `localStorage` (битый JSON, неверная структура) не ломают запуск: приложение стартует с пустого состояния, а после чтения данные проверяются в `afterHydrate`. Задачи из лабы №6 (ключ `todo:tasks`) не переносятся.

## Зависимости

| Пакет | Назначение |
| --- | --- |
| `vue` 3 | интерфейс (Composition API, `<script setup>`) |
| `pinia`, `pinia-plugin-persistedstate` | общее состояние и его сохранение в `localStorage` |
| `vue-router` | страницы и навигация |
| `vite`, `@vitejs/plugin-vue` | dev-сервер и сборка |
| `sass` | стили (`@use`/`@forward`, БЭМ, темы через CSS custom properties) |
| `gh-pages` | публикация `dist/` на GitHub Pages |

Требуется Node.js 20.19+ (или 22+) и npm.

## Команды

```bash
npm ci            # установить зависимости строго по package-lock.json
npm run dev       # dev-сервер Vite (http://localhost:5173)
npm run build     # production-сборка в dist/
npm run preview   # открыть собранную версию локально
npm run deploy    # собрать и опубликовать dist/ в ветку gh-pages
```

Свежеустановленные пакеты: `npm install pinia pinia-plugin-persistedstate vue-router`.

## `watch` и `v-if`

**`watch`** — для побочных эффектов: `useTheme` (применить и запомнить тему), `BaseModal` (вызвать `showModal()`/`close()` у `<dialog>`), `AddTodoModal`/`EditTodoModal` (подготовить поле при открытии), `TodoPage` (озвучить число показанных задач при смене фильтра). Сохранение в `localStorage` теперь выполняет `pinia-plugin-persistedstate`, а не ручной `watch`.

**`v-if`** — для того, чего в данный момент не должно быть в DOM: ошибки полей (`FormField`, модальные окна), сообщение об ошибке входа, уведомление об успешной регистрации, счётчик и пустой список (`TodoPage`, `TodoList`), содержимое закрытых модальных окон (`BaseModal`), пункты меню, недоступные гостю или вошедшему (`AppHeader`).
