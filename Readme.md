# To-Do List на Vue 3 и TypeScript

Лабораторная работа №9: перенос To-Do из лабораторной №7 на **TypeScript** и настройка проверок качества кода — **`vue-tsc`**, **ESLint** (flat config) и **Prettier**. Функциональность прежняя: регистрация, вход и выход, личные списки задач, четыре страницы и учебная авторизация.

- **Автор:** Беседин Кирилл Дмитриевич, ФИТ-241  
- **Опубликованное приложение:** https://sognatore-coder.github.io/To-doList_js/  
- **Node.js:** `^20.19.0 || ^22.13.0 || >=24` (проект проверен на Node.js 22 LTS), npm 10+

> ⚠️ **Авторизация учебная, без сервера.** Аккаунты (пароль в виде хэша с солью) и состояние входа лежат в `localStorage` браузера и доступны скриптам страницы. Это демонстрация сценария, а не защита реальных учётных записей: используйте только вымышленные email и пароли, которые нигде больше не применяются.

## Возможности

- **Регистрация и вход** — email, пароль и подтверждение; проверка формата email, длины пароля (от 6 символов), совпадения паролей и уникальности email. Неверные данные при входе дают ошибку. «Выйти» завершает только текущий вход.
- **Личные задачи** — каждая задача хранит `userId` владельца; на странице задач видны и изменяются только задачи текущего пользователя.
- **Операции To-Do** — добавление (модальное окно), редактирование, удаление с подтверждением, отметка выполненной (выполненные зачёркнуты и уходят вниз), поиск по названию и фильтры «Все / Активные / Готовые».
- **Четыре страницы** — вход, регистрация, задачи, «О приложении».
- **Тема** — светлая и тёмная, выбор запоминается.
- **Адаптивность и доступность (A1–A7 из лабы №4)** — подписи полей, `aria-describedby` и `role="alert"` для ошибок, `aria-current="page"` в навигации, управление с клавиатуры, видимый фокус, модальные окна на `<dialog>`, перенос фокуса при смене страницы.

## Маршруты и guard

| Путь         | Страница           | Доступ          |
| ------------ | ------------------ | --------------- |
| `#/login`    | `LoginPage.vue`    | только гостям   |
| `#/register` | `RegisterPage.vue` | только гостям   |
| `#/todo`     | `TodoPage.vue`     | только вошедшим |
| `#/about`    | `AboutPage.vue`    | всем            |

Guard в `router/index.ts` перенаправляет гостя со страницы задач на `#/login?redirect=/todo`, в том числе при открытии по прямой ссылке и после обновления страницы; после входа пользователя возвращают на запрошенную страницу. Используется `createWebHashHistory()`: адреса вида `…/#/todo` работают на GitHub Pages без перенаправления запросов на `index.html`.

## Команды

```bash
npm ci                # установить зависимости строго по package-lock.json
npm run dev           # dev-сервер Vite (http://localhost:5173)
npm run type-check    # проверка типов: vue-tsc (приложение и шаблоны) + tsc (vite.config.ts)
npm run lint          # ESLint, любое предупреждение — ошибка
npm run format:check  # проверка форматирования Prettier
npm run check         # type-check + lint + format:check (ничего не исправляет)
npm run lint:fix      # автоисправление ESLint (меняет файлы)
npm run format        # форматирование Prettier (меняет файлы)
npm run build         # check, затем vite build → dist/
npm run preview       # открыть собранную версию локально
npm run deploy        # собрать (с проверками) и опубликовать dist/ в ветку gh-pages
```

`check`, `lint`, `type-check`, `format:check` и `build` **не изменяют исходники**; файлы правят только явно запущенные `lint:fix` и `format`.


## Что проверяет `build` и чем проверка типов отличается от сборки Vite

`npm run build` = `npm run check && vite build`. Сначала выполняются **все статические проверки**, и только при их успехе запускается сборка; первая же ошибка останавливает команду (`dist/` при этом не создаётся).

1. **`type-check`** — `vue-tsc --noEmit -p tsconfig.json` проверяет типы в `src/**/*.ts` и в `.vue`-файлах, **включая выражения в шаблонах**; затем `tsc --noEmit -p tsconfig.node.json` проверяет `vite.config.ts`. Два `tsconfig` нужны, потому что код приложения выполняется в браузере (`types: vite/client`), а конфигурация Vite — в Node.js (`types: node`).
2. **`lint`** — `eslint . --max-warnings 0`: рекомендованные правила Vue и TypeScript, запрет явного `any`; предупреждения считаются ошибкой.
3. **`format:check`** — `prettier --check .`: файлы оформлены по `.prettierrc.json`.
4. **`vite build`** — собственно сборка в `dist/`.

**Vite не проверяет типы.** Он лишь убирает аннотации типов (транспилирует TypeScript в JavaScript), поэтому сборка пройдёт и с неверным типом, например с присвоением строки числовому полю. Ошибку покажет только `vue-tsc`/`tsc`, поэтому типы проверяются отдельным шагом до сборки. Проверка работает и как защита: изменение `filter: 'all'` на `'oops'` в сторе останавливает `build` с ошибкой `TS2322`.

## Типизация

- **Модели** — `Todo`, `TodoFilter`, `User`, `AuthResult`, `Theme` в `src/types/`; поля `meta` маршрутов (`title`, `requiresAuth`, `guestOnly`) описаны через `RouteMeta`.
- **Сторы Pinia** — типизированы состояние (`UserState`, `TodoState`), геттеры и действия; отсутствие пользователя обработано (`currentUser: User | null`, `myTodos` пуст для гостя).
- **Компоненты** — типизированные `defineProps<…>()` и `defineEmits<…>()`, DOM-ссылки `ref<HTMLInputElement | null>(null)` с проверкой на `null`, обработчики событий с проверкой `event.target instanceof HTMLInputElement`.
- **Данные из `localStorage`** — TypeScript их содержимое не проверяет, поэтому после `JSON.parse` (внутри `pinia-plugin-persistedstate`) значения читаются как `unknown` и проходят проверки `toUser` / `toTodo` в `afterHydrate`. Битый JSON или неверная структура не ломают запуск: приложение стартует с пустого состояния. Без `any`, `@ts-ignore` и утверждений типов.

## Сценарий проверки учебных пользователей и их задач

Все данные вымышленные. Проверка выполняется на `npm run preview` или на опубликованном сайте.

**1. Данные версии лабы №7 читаются после переноса.**

1. На версии лабы №7 (ветка `lab-7` или её опубликованная сборка) зарегистрируйте `user1@test.ru` / `secret1`, войдите, добавьте две задачи, отметьте одну выполненной. Выйдите, зарегистрируйте `user2@test.ru` / `secret2`, войдите, добавьте задачу «Чужая».
2. Откройте новую версию **на том же адресе** (тот же origin и `localStorage`; для локальной проверки — запустите `npm run preview` на порту, где открывалась старая сборка).
3. Войдите как `user1@test.ru` / `secret1`: вход проходит, видны обе задачи, отметка выполнения сохранена. Выйдите и войдите как `user2@test.ru`: виден только список из одной задачи «Чужая».
4. В DevTools → Application → Local Storage ключи прежние: `todo-app:users`, `todo-app:todos`, `todo:theme`; поля задачи — `id`, `userId`, `title`, `done`. Формат хранения не менялся, миграция не нужна.

**2. Сценарии приложения.**

- Откройте `#/todo` без входа — произойдёт переход на `#/login`; после входа вы вернётесь на `#/todo`. Обновите страницу — сессия сохраняется.
- Регистрация: неверный email, пароль короче 6 символов, разные пароли, повторный email — у каждого случая своя ошибка.
- «Выйти», затем вход под другим пользователем — списки задач разные; при повторном входе каждый видит свои задачи.
- Добавление, редактирование, удаление, отметка выполненной, поиск, фильтры, переключение темы.
- Прямые ссылки `…/#/about` и `…/#/todo` и перезагрузка страницы на опубликованном сайте.

**3. Устойчивость к повреждённым данным.** Запишите в `todo-app:users` или `todo-app:todos` значение `{bad`, `null` или `[1,2]` и обновите страницу: приложение запускается с пустым состоянием, без ошибок в консоли.
