# To-Do List на Vue 3

Лабораторная работа №6: перенос To-Do List (Sass + vanilla JS) на **Vue 3 (Composition API)** и **Vite**.

- **Автор:** Беседин Кирилл Дмитриевич  
- **Группа:** ФИТ-241
- **Опубликованное приложение:** https://sognatore-coder.github.io/To-doList_js/

## О проекте

Список дел с хранением в `localStorage`. Все пользовательские сценарии лабораторной №4 сохранены.

- добавление задачи через модальное окно, редактирование (тоже в модальном окне), удаление с подтверждением, отметка выполненной;
- выполненные задачи зачёркиваются и уходят вниз списка;
- поиск по названию, фильтрует список по мере ввода; фильтры «Все / Активные / Готовые»;
- светлая и тёмная темы, выбор запоминается (по умолчанию — системная тема);
- задачи, названия и отметки сохраняются после перезагрузки; пустое или некорректное содержимое хранилища не ломает запуск — приложение стартует с пустым списком;
- адаптивная вёрстка (mobile-first) и доступность A1–A7 из лабораторной №4: семантическая разметка, подписи полей, `aria-labelledby` на основе `id` задачи, `aria-pressed`, live-область, видимый фокус, модальные окна на `<dialog>` (фокус-ловушка, `Esc`, возврат фокуса), `prefers-reduced-motion`.

## Стек и зависимости

| Пакет | Назначение |
| --- | --- |
| `vue` 3 | интерфейс (Composition API, `<script setup>`) |
| `vite`, `@vitejs/plugin-vue` | dev-сервер и сборка |
| `sass` | стили (Sass: `@use`/`@forward`, БЭМ, темы через CSS custom properties) |
| `gh-pages` | публикация папки `dist/` на GitHub Pages |

Требуется Node.js 20.19+ (или 22+) и npm.

## Команды

```bash
npm ci            # установить зависимости строго по package-lock.json
npm run dev       # dev-сервер Vite с HMR (http://localhost:5173)
npm run build     # production-сборка в dist/
npm run preview   # локально открыть собранную версию из dist/
npm run deploy    # собрать и опубликовать dist/ в ветку gh-pages
```

Данные идут вниз через `props`, действия дочерних компонентов — вверх через `emit`. Состоянием владеют `App.vue` и composables; компоненты о `localStorage` ничего не знают.

## Где и зачем применены `watch` и `v-if`

### `watch`

`watch` нужен там, где изменение данных должно вызвать **побочный эффект**, а не новое производное значение (для производных данных использован `computed` — `visibleTodos`, `remaining`, `editingTodo`).

- `useTodos.js` — `watch(todos, …, { deep: true })` записывает список в `localStorage` при любом изменении (добавление, правка, удаление, отметка), поэтому ни один обработчик не вызывает сохранение вручную.
- `useTheme.js` — `watch(theme, …)` ставит `data-theme` на `<html>` и запоминает выбор.
- `BaseModal.vue` — `watch(() => props.open, …)` вызывает `showModal()` / `close()` у нативного `<dialog>`: это императивное DOM-API, которое нельзя выразить шаблоном.
- `AddTodoModal.vue`, `EditTodoModal.vue` — очищают или заполняют поле ввода при открытии окна; редактирование идёт в локальной копии названия и не меняет список до «Сохранить».
- `App.vue` — `watch(filter, …)` озвучивает скринридеру число показанных задач после смены фильтра.

### `v-if`

`v-if` убирает из DOM то, чего в данный момент не должно быть, — это важно и для вёрстки, и для доступности.

- `TodoList.vue` — `<ul v-if>` / `<p v-else>`: пустой список не рендерится, вместо него подсказка («Задач пока нет» или «Ничего не найдено»).
- `App.vue` — счётчик «Осталось сделать» показывается, только если есть задачи.
- `BaseModal.vue` — `<slot v-if="open">`: содержимое окна существует, только пока оно открыто, поэтому форма каждый раз создаётся заново, без остатков прошлого ввода.
- `AddTodoModal.vue`, `EditTodoModal.vue` — сообщение об ошибке с `role="alert"` появляется только при невалидном вводе (так скринридер озвучивает его при появлении).
